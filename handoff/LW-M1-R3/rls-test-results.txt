RUN NOTES
--------------------------------------------------------------------------------
* All 30 probes above ran against the LIVE lorewish-dev project (sfarcofvqfeobtcizxyv)
  AFTER migration 20260810065727_m1_least_privilege_hardening was applied.

* The Auth Admin API is fronted by Cloudflare. A first attempt at the ephemeral-account
  setup, using node's default fetch User-Agent, was answered with a Cloudflare WAF
  challenge page (HTTP 403 "Sorry, you have been blocked") rather than by GoTrue. This
  is an edge/bot-protection response, not an authorization failure, and it is unrelated
  to the privilege work in this task. The run was repeated with a browser-shaped
  User-Agent and completed normally. No test accounts were created by the blocked
  attempt, so it left nothing behind to clean up.

* Cleanup is verified, not assumed: the suite re-reads the deleted Story (200 [], gone),
  deletes both ephemeral users via the Auth Admin API (200/200 each), and then lists the
  project's users and counts any remaining @lorewish-test.dev addresses. That count was
  0. Child rows (worlds, characters, story_configurations) went with the Story via
  ON DELETE CASCADE.

* The R2 suite treated `200 []` for an anonymous read as a pass. That is a weaker
  assertion than this run makes and it is deliberately no longer accepted: probes
  A1.*, A2 and A3 require SQLSTATE 42501 with a "permission denied for table ..."
  message, which can only come from the object-privilege layer. Every one of them
  returned HTTP 401 with exactly that, including PostgREST's own hint naming the grant
  that would be needed ("GRANT SELECT ON public.stories TO anon;") — which is direct
  confirmation that no such grant exists.
