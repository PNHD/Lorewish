LW-M2-R2 — Latency Summary (REAL LIVE DATA)
==============================================
Measured end-to-end around each provider's HTTP call (performance.now() delta in the adapter),
n=12 per model except gemini-3.6-flash (partial, quota-blocked). Small sample sizes — not
over-interpreted, per the task brief's instruction. Full per-case data: bakeoff-raw/*.json.

gemini-3.5-flash-lite (n=12)
  Median: 2,243ms   Min: 1,763ms   Max: 2,713ms
  Fastest of the four models actually completed.

deepseek-v4-pro (n=12, post thinking-mode fix)
  Median: 12,421ms   Min: 9,498ms   Max: 20,026ms
  Substantially slower than either Gemini tier even with thinking disabled — DeepSeek's
  output token counts for the same cases ran 2-4x higher than Gemini's (see cost-summary.txt /
  narrative sample notes), which likely explains most of the latency gap.

deepseek-v4-flash (n=12, post thinking-mode fix)
  Median: 6,808ms   Min: 5,626ms   Max: 11,182ms
  Roughly half deepseek-v4-pro's latency, consistent with its role as the faster tier.

gemini-3.6-flash (n=12, PARTIAL — quota-blocked before a clean 2nd pass; pre-fix sample only)
  Median: 9,533ms   Min: 6,945ms   Max: 14,905ms
  Not directly comparable to the other three: this sample predates the thinking-token
  accounting fix, so the visible latency includes an unknown, uncounted amount of server-side
  "thinking" time in addition to whatever's reflected in the token counts. A clean re-run is
  needed once the daily quota resets.

Before-vs-after (DeepSeek thinking-mode fix, same cases, same models):
  deepseek-v4-pro:   pre-fix median 19,489ms  ->  post-fix median 12,421ms  (~36% faster)
  deepseek-v4-flash: pre-fix median 10,895ms  ->  post-fix median  6,808ms  (~38% faster)
  Disabling unnecessary reasoning tokens measurably improved latency as well as reliability
  and cost — a three-for-one fix.
